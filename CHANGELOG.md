# Changelog

All notable changes are documented here. The project follows semantic versioning for public Python/CLI behavior.

## 5.0.0

### Fully owned runtime

- Replaced the v4 external/library-backed architecture with a repository-owned PDF engine implemented under `pdf2pdfa/native`.
- Runtime dependencies are now **zero**; the installed package uses Python standard-library modules and repository-owned source only.
- Removed Ghostscript, veraPDF, pikepdf, fontTools, Pillow and Click from the runtime architecture and deleted the obsolete adapters/backends.
- Removed bundled third-party ICC assets; default profiles are generated by owned code.
- Added ownership tests that AST-scan every distributed Python module and fail on non-stdlib/non-owned imports.

### PDF engine

- Added tokenizer, COS object model, indirect-object resolver, classic xref parser, xref-stream parser, object streams, incremental update chains and repair-mode xref rebuilding.
- Added deterministic writer with reachable-object serialization and classic xref output.
- Added Flate, ASCIIHex, ASCII85, RunLength, LZW and predictor handling in owned stream code.
- Added PDF content-stream parser including inline images.

### PDF/A validation

- Added owned PDF/A-1b, PDF/A-2b and PDF/A-3b rule engine.
- Validation is mandatory for rewritten output and can no longer be disabled through the public API/CLI.
- Validation failures expose rule id, clause, message and object/path.
- Added profile-specific checks for file structure, metadata/XMP, actions, annotations, fonts, color, OutputIntent/ICC, forms, optional content, attachments and PDF/A-1 transparency restrictions.

### Repair and preservation

- Added owned structural repair planner and fail-closed blocker model.
- Added removal/normalization of forbidden actions, encryption, stream/filter issues, forms/annotation flags, profile-incompatible attachments, optional content, metadata and color structures where repair is provably safe.
- Added atomic candidate publication; an existing destination is preserved on any repair, validation or fidelity failure.
- Already-conforming unencrypted files pass through byte-for-byte.

### Security

- Added owned Standard Security Handler implementation including RC4 and AES handling for supported PDF security revisions.
- Encrypted input is decrypted in-process; passwords never leave the Python process.
- Applied digital signatures remain blocked by default before a rewrite can invalidate them.

### Fonts and rendering

- Added owned SFNT/TrueType parser, cmap/metrics handling, safe font embedding and TrueType glyph outline rendering.
- Added Type0/CIDFontType2 handling for owned rendering where encoding/CID mapping is understood.
- Added color spaces, ICC transforms, function evaluation, JPEG decoding, image masks/soft masks and affine image painting.
- Added pure-Python raster surface, vector paths, clipping, affine-correct strokes, text and page rendering.
- Added transparency compositor with opacity, blend modes, soft masks and isolated transparency-group support.

### PDF/A-1 transparency flattening

- Added selective owned raster flattening for pages whose used painting instructions require PDF/A-1 transparency removal.
- Preserves page geometry and `/Rotate`, detaches forbidden transparency resources and embeds an opaque Flate RGB page image.
- Annotation appearance streams are protected fail-closed when resource inheritance would make flattening ambiguous.

### Fidelity

- Added semantic fidelity fingerprinting for structural rewrites.
- Added native visual fidelity that renders source/candidate through the same owned renderer and compares RGB pixels in memory.
- Added `auto`, `semantic`, `visual` and `off` modes; `auto` upgrades to visual fidelity when page painting is intentionally rewritten.

### Public API and CLI

- Replaced backend-oriented `Converter` with the owned `OwnedPDFAPipeline` facade.
- Added `Converter.inspect()`, `Converter.validate()` and conversion-plan results.
- Removed backend selection and optional validator switches.
- Replaced Click with stdlib `argparse`.
- CLI commands are `convert`, `batch`, `inspect`/`preflight` and `validate`.
- Added JSON output for inspection, conversion and validation workflows.

### Tests and release engineering

- Replaced legacy pikepdf/Ghostscript/veraPDF fixtures with generated owned-engine fixtures and native regression suites.
- Added module-graph integrity tests to catch missing internal modules/import failures.
- Added public API and package-ownership contracts.
- Replaced external-tool E2E smoke tests with owned 1b/2b/3b conversion/validation/fidelity smoke tests.
- Push/pull-request CI remains intentionally disabled; the only GitHub workflow is tag-triggered package publication.

### Fail-closed gaps

The v5 engine deliberately refuses a transformation when an owned implementation is not available. At this stage those paths include several CFF/Type1/Type3 text cases, predefined non-Identity CMaps, JPX/JBIG2/CCITT image decoding needed for rendering, and non-isolated/knockout transparency-group rendering. They are not delegated to external software.

## 4.0.0

### Architecture

- Replaced the single mutation pipeline with profile-aware preflight plus adaptive backend orchestration.
- Added conservative pikepdf fast path and optional Ghostscript full-rewrite fallback.
- Added atomic publication so failed backend, validation or strict-fidelity checks preserve an existing destination.
- Added passthrough for already-valid PDFs after veraPDF confirmation.

### Compliance

- veraPDF validation parses the requested flavour and `validationReport@isCompliant` rather than trusting process exit status or XMP claims.
- PDF/A-1b, 2b and 3b gained separate profile policies.

### Preservation fidelity

- Added optional raster fidelity reports through the v4 external renderer stack.

### Security

- Added encrypted-PDF handling, size limits and default refusal of applied digital signatures.

### Packaging

- Python requirement moved to 3.10+.
- Push/pull-request CI workflows were removed by project policy.

## 3.1.0

- Added selectable PDF/A-1b, PDF/A-2b and PDF/A-3b metadata targets.

## 3.0.0

- Added per-font system resolver, resource color-space handling, batch conversion and optional external validation.

## 2.0.0

- Improved ICC stream metadata, CMYK handling and basic font metrics; added batch/validation CLI options.
